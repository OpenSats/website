### Bdk-cli

[Bdk-cli] is a command-line Bitcoin wallet tool built using [Bitcoin Dev Kit]
(BDK). It allows developers to create and experiment with
[descriptor-based wallets], test spending conditions, and explore Bitcoin
features like [Taproot] using a practical command-line interface. The project
also provides an easy entry point for contributors learning the Rust Bitcoin
development environment. Although this is part of the broader BDK project,
bdk-cli is maintained by community contributors outside the BDK Foundation's
dedicated funding scope. Developer [Vadim Anufriev] has already contributed
features to the tool, including a change that randomizes unspendable internal
keys in Taproot descriptors to address privacy concerns.

This grant will support Vadim's continued development and maintenance of
bdk-cli, with particular focus on reviewing contributions from other
developers. Planned work includes a follow-up verification command for
Taproot unspendable internal keys and review of features involving
[BIP-329] wallet labels, [BIP-353] payment instructions, multipath
descriptors, [Payjoin] persistence, [Silent Payments], and signing device
integration. Compatibility will be maintained with upstream changes to BDK,
while addressing bugs, improving tests, and keeping continuous integrations
working. Pull request reviews will be prioritized to help newer developers
move their contributions forward.

### Cashu-TS and Cashu.me

[Cashu-TS] is a TypeScript library for building Bitcoin [ecash] wallets and
applications using the [Cashu protocol]. Cashu uses blind signatures that
allow mints to verify ecash tokens without being able to directly trace them
back to their original issuance. The library gives developers a common
implementation of the protocol and its respective [NUT specifications],
including tools for interacting with Cashu mints, handling tokens, and
building wallet functionality. [Cashu.me] remains an actively maintained web
wallet built with Cashu-TS, while the newer [native iOS and Android apps] use
CDK bindings. OpenSats supported Cashu-TS development through a prior grant,
with this grant specifically supporting Rob Woodgate's work as a maintainer
of the library, Cashu.me, and the underlying protocol specifications.

Rob has made numerous contributions to Cashu-TS, including the [v3] redesign
and the [v4] release, which enhanced wallet operations with support for
larger, precision-safe amounts. Development of [v5] is already underway, with
releases including new protocol features and changes to ecash proof handling.
Rob plans to continue developing and maintaining the library to keep it in
line with evolving NUT specifications, making its APIs practical for
application developers. He will also contribute to [Cashu.me]
[Cashu.me website] as a co-maintainer, working on the wallet's implementation
and security, while continuing his reviews and refinement of the Cashu
protocol specifications.

### Code Orange Dev School

[Code Orange Dev School] is a Bitcoin developer education program founded by
keypleb, based in Bali, Indonesia. Code Orange offers a structured path,
utilizing hands-on workshops and technical study cohorts to contribute code
for open-source Bitcoin projects. Programs such as Bitcoin Dojo, rawBit, and
Decoding Bitcoin introduce developers to Bitcoin's technical foundations
before helping them work on repositories including [Bitcoin Core],
[rust-bitcoin], [BDK], and [rust-payjoin]. Code Orange also has a
[public dashboard] tracking pull requests across Bitcoin projects.

This grant will support a year-long Bitcoin Privacy Developer Track, with 24
biweekly sessions covering chain analysis, [Silent Payments],
[Payjoin], network privacy, and advanced techniques involving [CoinJoin],
[Lightning], and [ecash]. The program sessions combine technical study with
practical contributions on existing issues and pull requests to guide
students to work on privacy-focused repositories. The grant will also support
two different six-month fellowship cohorts, providing mentorship to four
developer fellows working on specific open-source projects and four educator
fellows to run workshops, lead study cohorts, and train additional
instructors. Code Orange's goal is to train more than 40 developers and
target the opening of at least 30 pull requests on privacy-related projects
over the next year.

### Dana

[Dana] is an experimental mobile Bitcoin wallet designed around
[Silent Payments], a protocol that allows users to receive payments through a
reusable payment code without revealing a reused on-chain address. The wallet
uses [BIP-353] to provide payment addresses in a format that looks like email
addresses (e.g., ₿donate@danawallet.app). Dana's privacy-focused scanning
approach aims to limit what its public backend can learn about users' payment
activity. OpenSats has [previously supported Dana Wallet], and this grant
will support developer [Sosthène's] continued work on the project.

Project developer Sosthène will use his grant to focus on moving Dana toward a
production-ready Android release, with additional work on scanning
performance, deployment, and general wallet stability. The majority of
development work will be to refine the contacts-centric interface, allowing
users to send bitcoin to saved contacts without having to manage traditional
bitcoin addresses. The project will also explore features designed
specifically for donations, including the possibility of offering users an
option to donate change left over from transactions to a cause the user
supports.

### Libbitcoin

[Libbitcoin] is a modular C++ Bitcoin development toolkit and independent full
node implementation. In development since 2011, the project provides reusable
libraries for cryptography, database operations, peer-to-peer networking,
blockchain validation, and command-line tools. The architecture prioritizes
parallel processing and the efficient use of available hardware during
blockchain synchronization and validation. OpenSats has[previously supported]
development of [Libbitcoin v4], and this additional grant supports
[Rowan's] work on the user-facing interfaces for the upcoming release.

Rowan will focus on completing the embedded browser-based block explorer and
developing an administrative dashboard for Libbitcoin Server. The explorer
will have an interface for inspecting blockchain data, while the dashboard
will allow node operators to manage server configuration and inspect
diagnostic information, synchronization progress, and performance metrics.
The dashboard is designed for displaying live information from the node
through secure HTTP and WebSocket interfaces. Rowan will also test the node
using different configurations and compiler flags to measure what effects
they have on performance. He plans to publish a series of previews and
release candidates ahead of the Libbitcoin v4.0 release.

### OrangeCheck

[OrangeCheck] is a family of open protocols, developed by [Wil], used for
creating Bitcoin-linked digital identities and verifiable claims on the web.
There are six components, [Attest], for identity attestation, [Lock], for
secure communication, [Stamp], for content provenance, [Vote], for community
signaling, [Agent], for delegated authority, and [Pledge], for commitments.
OrangeCheck's main implementation is [ochk.app], where a user signs in
through [OAuth] (Google or GitHub), email, or a Bitcoin wallet to receive a
Bitcoin identity in the background, signed with [BIP-322]. OrangeCheck holds
custody while the app is in testing, with plans to move to [Fedimint] and
then to the user's own keys. Anyone can check a signed envelope on any
machine, using only the envelope itself and public Bitcoin data. It's also
possible to verify if a signed envelope has been published on a
[nostr relay].

The grant will fund work on a reusable reference implementation and the
protocol layer. Wil plans to build up to three live integrations with design
partners, to then leverage his learnings to improve the SDKs and
documentation. From there, integrations will expand to provenance, voting,
agent permissions, and pledges, each with example code that other developers
can copy and modify. The last phase will be about reaching v1. This means
stabilizing the SDKs and getting the signing and verification code to be
audited through independent security review. If time allows, Wil hopes to get
OrangeCheck's nostr spec ([NIP]) accepted upstream.

### Stratum V2 Reference Implementation

The [Stratum V2 Reference Implementation] (SRI) is an open-source
implementation of the [Stratum V2 mining protocol], providing libraries and
applications for miners and mining pools. Stratum V2 improves communication
between mining equipment and pools using a more efficient binary protocol and
authenticated, encrypted connections. SRI's job negotiation capabilities
allow participating miners to build their own block templates, reducing
dependence on pool operators for transaction selection. OpenSats has
supported other Stratum V2 contributors in [earlier grants], and this grant
will specifically support [bit-aloo's] work on the reference implementation.

Bit-aloo's focus area will be improving the reliability and maintainability of
the protocol libraries as SRI sees wider adoption, including refactoring
low-level components such as [`binary-sv2`](message encoding and decoding),
[`noise-sv2`](encrypted communication), and [`framing-sv2`](message framing),
addressing technical debt while simplifying future development. Another
milestone will include a deterministic simulation testing framework to
reproduce elusive bugs, especially concurrency issues. Bit-aloo will also
work on performance benchmarks, integration tests under real world
conditions, and review pull requests. These tests should help catch problems
before updates reach mining infrastructure.

### Tor Network-Combatting Malicious Relays

The [Tor Project] develops and maintains the [Tor network], a decentralized
system routing encrypted traffic through volunteer-operated relays with the
goal of protecting users against network surveillance and censorship. Tor is
widely used throughout the Bitcoin ecosystem, including node operators who
use onion services to increase the privacy and security of their network
addresses. Tor’s distributed network reduces dependence on a single operator,
but malicious relays can still join the network and pose a threat to user
privacy and security. In 2020, the Tor Project [identified and removed]
groups of exit relays that intercepted connections to cryptocurrency
exchanges, preventing users from being redirected from unencrypted HTTP
connections to more secure HTTPS. OpenSats has [supported Tor development]
before, but this grant will fund a different group of developers working
specifically on detecting and investigating malicious relays.

The Tor Project has already developed a database of network status information
that can be queried to help investigators identify and neutralize coordinated
attacks. However, inspecting suspicious relays and determining if independent
operators are connected to them still involves extensive analysis. This grant
will fund work on a more proactive investigation framework using behavioral
anomalies and correlations between relay activity to identify potential
threats. This approach will combine indications of malicious behavior with
less obvious signals which may reveal coordinated operators or emerging
attacks. This enables investigators to examine suspicious activity much
earlier and more efficiently.

Over their grant period, the Tor team will establish a common data format
across existing tools and incorporate external data sources into a
centralized network health database. This will be followed by alerts based on
historical patterns, a platform for investigating suspicious relay operators
and their connections, and datasets and visualizations that can be queried to
support further analysis as needed. The intention of these tools are to
reduce the time required to investigate malicious relay groups and improve
the Tor Project's ability to respond to threats. Bitcoin users and node
operators dependent on Tor for network privacy will benefit from improved
detection of attacks that could compromise their connections or expose
sensitive information.

### Rust-bitcoin

Mpbagot has been an OpenSats grantee since [January 2026][January 2026
(rust-bitcoin)]. He is part of the several grantees that are working on
`rust-bitcoin`, the low-level Bitcoin library written in Rust that most of
the projects built on the same language rely on. Mpbagot has been focusing on
crate smashing — a technique whose goal is to divide bigger libraries
(“crates”, as they are called in the Rust ecosystem) into smaller ones. In
particular, he worked on the new `units` crate, adding new proof-of-work
related types, on the separation of the cryptographic libraries into a
dedicated `crypto` crate, and on the migration of PSBTs to `rust-psbt`. With
support from this second grant, mpbagot will be focusing on stabilising
`rust-secp256k1` — the Rust wrapper based on the [libsecp256k1] C library
used in Bitcoin Core — with the objective of releasing a first release
candidate for v1.0.

### Fully Noded

Fontaine has been an OpenSats grantee since [December 2023]. He has been

### BitaxeBonanza

[Skot] has been an OpenSats grantee since [January 2024]. He has been working
on [Bitaxe], an open-source mining hardware that works with several ASIC
chips, with the final goal to decentralize mining by open-sourcing the
hardware needed. During the years, Skot has released several boards
supporting different ASICs, such as the BitaxeSupra, BitaxeUltra, and, more
recently, the BitaxeGamma. With support from this new grant, Skot and
Johnny9 — a first-time grantee that has been working with on Bitaxe for
several years, developing firmware for the various open-source miners — will
work together on [BitaxeBonanza], a new hardware based on the Intel BZM2
ASICs. The objective is to have a fully functional, validated Bitcoin miner
by the end of the grant period.

### Tollgate and FIPS

Arjen has been an OpenSats grantee since [January 2025]. At the time, he was
working on Nostr Epoxy, a nostr-based WebSocket proxy that acts as a bridge
between different networks to enable reliable connectivity. With support from
this second grant, Arjen will be working on [TollGate], a project that turns
